Guide

what each field means
1 · Which file do I upload?

The PDF export of a scan, as the scanner's own "export report" or "download PDF" button produces it. Not the XML, CSV or HTML export: MulitaMiner's profiles are written against the PDF layouts.

One report per job. Up to {{ max_mb }} MB; the largest sample in the project (a Qualys scan with 1,053 findings) is 5 MB.

The PDF and the results are deleted {{ retention_h }} h after the job finishes. If the report is sensitive, run it through AnonShield first and upload the pseudonymized copy.

2 · What is a scanner profile?

A small JSON file describing one vendor's PDF layout: the pattern that opens a finding, where the host and port appear, which labels mark the description, solution and references, plus the prompt that explains the layout to the model.

3 · Which model, and where do I get a key?

Every model speaks the same OpenAI-style API. The model reads each finding and fills the record; the rest of the pipeline is the same whichever you choose.

Cost. You pay the provider directly. A 34-finding OpenVAS report cost about US$0.02 on DeepSeek; a 1,053-finding Qualys scan, about US$0.50. The job page shows the estimate.

Time. Small reports finish in under a minute; a 150-finding Tenable report takes around 40 minutes, the 1,053-finding Qualys one about two hours. Jobs run one at a time and you keep the link.

Your key is sent with the form, kept in memory while the job runs and dropped when it finishes. It is never written to disk or to a log, and provider error messages that contain it are replaced. The server operator could still read it in flight, so use a key with a spending limit and rotate it if in doubt.

4 · Custom endpoint: the profile fields

Pick "Custom OpenAI-compatible endpoint" to use any provider or server not in the list: Mistral, Together, OpenRouter, a vLLM or llama.cpp server you expose, and so on. The JSON has the same fields the CLI reads from configs/llms/*.json:

FieldMeaning
keyA short name for this profile. Shown on the job page; any string.
modelThe provider's model id, exactly as its API expects it (mistral-large-latest, qwen2.5:7b…).
base_urlThe API root, usually ending in /v1. The tool calls base_url + /chat/completions.
context_windowTokens the model can take in one request (prompt + answer). Sets how many findings go in one chunk. For Ollama it is also sent as num_ctx.
max_output_tokensLongest answer the model may return. Findings are packed so the expected answer fits; too small means more, smaller chunks.
supports_json_schematrue if the endpoint accepts a JSON schema as response_format (OpenAI, Ollama, vLLM). false falls back to "JSON object" mode plus the schema in the prompt.
reasoning_tagstrue for models that wrap thinking in <think> tags (Qwen3, DeepSeek-R1); the tags are stripped before parsing.
reasoning_effort"low", "medium", "high" or "none" for thinking models; omit otherwise.
temperatureDefaults to 0: extraction should be deterministic.
request_timeout_sSeconds to wait for one answer, default 120. Raise it for slow servers (CPU inference).
price_in, price_outUS$ per million input and output tokens, only for the cost estimate. Default 0.
encodingTokenizer used to budget chunks, default cl100k_base. Leave it.

Not accepted here: api_key_env. On the CLI it names the environment variable that holds the key; on the web the key field does that job. Fill it for a keyed provider, leave it empty for a keyless local server.

5 · What happens after I click Extract?
  • Read and segment: the PDF becomes numbered blocks, one per finding. Seconds.
  • Extract: blocks go to the model in chunks; the page counts findings as they come back. Missing ones are retried in smaller groups.
  • Consolidate: duplicates merge, severity and CVSS are normalised.
  • Download: XLSX or CSV, one row per finding, the same columns for every scanner.

If something fails (wrong profile, rejected key, provider outage), the job page shows the reason and your upload stays {{ retention_h }} h so you can resubmit with a fix.
